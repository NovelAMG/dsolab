DevSecOps Lab — SPA + n8n + Azure OpenAI on AKS

Entra-auth only · Phased learning lab from "no DevOps" to fully instrumented DevSecOps pipeline.

Phase 1 builds a working pipeline with zero security gates (pure DevOps muscle memory). Phases 2–5 progressively layer in GHAS (shift-left), Defender for Containers (runtime), Defender for AI Services + Purview DSPM (AI SPM), and Conditional Access. Phase 5 detonates CVE-2025-68613 (n8n authenticated RCE) in an isolated namespace to validate every detection layer end-to-end.

AKS only GitHub Actions + OIDC (no secrets) Terraform (azurerm + azuread + azapi) Azure OpenAI Entra-only (disableLocalAuth) oauth2-proxy at ingress Workload Identity for AOAI tokens
Defender posture for Phase 1: plan stays enabled at the subscription level (agentless image scan + posture recommendations are free signals). The Defender sensor DaemonSet and Azure Policy for Kubernetes add-on are explicitly disabled in Defender for Containers → Settings until Phase 3 so the cluster stays clean for the DevOps learning phase. Re-enable deliberately in Phase 3 as the "now I want runtime threat detection" milestone.
Teaching contract: every Phase 1+ task uses five labels — Do Git Verify Why Gotcha. Git convention: branch per task (<type>/<slug>), Conventional Commits (<type>(<scope>): <subject>), PR per branch, self-merge in Phase 1 (branch protection enforces gates in Phase 2+).

Mental model — container supply-chain attack lifecycle

Every phase maps to one stage of the attack lifecycle. When you finish, you'll have a defense at each stage.

Attack stageAttacker actionDefense in this labPhase
Code — supply chainMalicious code in image deps or app deps (typosquat, dep confusion, compromised maintainer)GHAS Dependabot + dep review + CodeQL; Defender for DevOps posture finds risky repo settings2A.1, 2B
Build — poisoning CI/CDPlant malware in workflow steps; steal CI secrets; abuse self-hosted runnersOIDC (no secrets) + branch protection + signed commits + Defender for DevOps posture1A, 2A.1, 2B
Ship — artifact tamperingModify/replace images in registries; swap tags; MITM on pullcosign keyless + SBOM + Defender for Containers registry scan + ACR private endpoint2E, 3.3
Deployment — misconfigurationPrivileged pods, hostPath mounts, secrets in env, missing NetworkPolicyPod Security Admission restricted + KV CSI + NetworkPolicy + Ratify + AFD + WAF3.2, 3.3
Runtime — vulnerable appExploit a known CVE; reverse shell; container escape; abuse workload identityDefender for Containers DaemonSet + drift protection + CA on workload identity + Defender for AI + MSEM attack-path3, 4, 5, 6

Phase 5 (CVE-2025-68613 detonation) deliberately walks an attacker down all 5 stages so you can score the defenses end-to-end.

  • User → SPA (Entra MSAL) → bearer token for the n8n API app reg → oauth2-proxy validates and injects X-Auth-* headers → n8n.
  • n8n pod uses Azure Workload Identity to fetch its own Entra token for cognitiveservices.azure.com/.default, then calls Azure OpenAI with Authorization: Bearer <token>.
  • Azure OpenAI has disableLocalAuth: true in Terraform — no API key exists, ever.
  • End-user context for Defender for AI attribution: user field in OpenAI body = OID from oauth2-proxy.
